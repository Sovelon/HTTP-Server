# HTTP-Server

Многопоточный HTTP/1.1-сервер на C++20. Долгосрочное домашнее задание по курсу «Многопоточное программирование на C++».

**Вариант 2: классический пул потоков.** Фиксированное число воркеров и одна общая очередь задач, защищённая `std::mutex` и `std::condition_variable`.

## Требования

- Linux x86_64 (проверка проходит на Linux), GCC ≥ 12 или Clang ≥ 15
- CMake ≥ 3.20
- Только POSIX sockets. Готовые HTTP- и event-loop-библиотеки не используются.

## Сборка и запуск

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j
./build/server --port 8080 --threads 8
```

| Параметр | Описание |
|----------|----------|
| `--port` | порт для прослушивания |
| `--threads` | число рабочих потоков в пуле |

Сервер завершается по `SIGINT` и `SIGTERM`. Он перестаёт принимать соединения, дорабатывает текущие запросы и останавливает потоки через `join`.

## Архитектура

```
              ┌──────────────┐   fd    ┌──────────────────────┐
  клиенты ──▶ │ поток-acceptor│ ──────▶ │ общая очередь задач  │
              │ accept()      │         │ mutex + condvar      │
              └──────────────┘         └──────────┬───────────┘
                                                  │ pop
                       ┌───────────────┬──────────┴────┬───────────────┐
                       ▼               ▼               ▼               ▼
                  воркер 1        воркер 2        воркер 3   …    воркер N
              read → parse → handle → serialize → write (keep-alive цикл)
                                       │
                                       ▼
                               хранилище items
```

- **Acceptor** — один поток, который вызывает `accept` и кладёт принятое соединение в очередь.
- **Очередь** — одна общая, под `std::mutex`. Воркеры ждут на `std::condition_variable`, acceptor вызывает `notify_one`.
- **Воркеры** — `--threads` потоков, создаются при старте. Воркер берёт соединение и обслуживает его целиком в цикле keep-alive: читает запрос, парсит, обрабатывает, пишет ответ.
- **Остановка** — флаг остановки и `notify_all`. Воркеры доделывают текущие запросы и завершаются, затем главный поток делает `join` для всех.

## Хранилище

Коллекция `item` лежит в памяти. Поля: `id`, `name`, `value`, `version`.

- `id` монотонно растёт и выдаётся через `std::atomic<uint64_t>`, поэтому он уникален даже при параллельных POST.
- `version` увеличивается при каждом изменении.
- PUT и PATCH поддерживают оптимистичную блокировку: если переданный `version` не совпадает с текущим, ответ 409.
- `POST /items/{id}/increment` выполняется атомарно под блокировкой хранилища, так что гонок нет.

## API

Тела запросов и ответов — JSON (`Content-Type: application/json`).

| # | Метод | Путь | Описание | Ответ |
|---|-------|------|----------|-------|
| 1 | GET | `/health` | проверка живости | 200 `{"status":"ok"}` |
| 2 | GET | `/items?offset=0&limit=100` | список с пагинацией | 200 |
| 3 | GET | `/items/{id}` | получить объект | 200 / 404 |
| 4 | POST | `/items` | создать (`name`, `value`) | 201 + объект |
| 5 | PUT | `/items/{id}` | полностью заменить | 200 / 404 / 409 |
| 6 | PATCH | `/items/{id}` | частично обновить | 200 / 404 / 409 |
| 7 | DELETE | `/items/{id}` | удалить | 204 / 404 |
| 8 | POST | `/items/{id}/increment` | атомарно увеличить `value` на `delta` | 200 + объект / 404 |

Используемые коды: 200, 201, 204, 400, 404, 405, 409, 500. Некорректный запрос не должен ронять сервер.

Пример объекта:

```json
{ "id": 42, "name": "string", "value": 0, "version": 1 }
```
